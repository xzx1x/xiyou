摘    要
高校心理咨询工作涉及大量敏感信息，传统纸质记录或普通信息系统难以兼顾隐私保护、过程留痕与责任追溯，容易出现数据分散、权限控制薄弱、记录可篡改等问题。针对上述现状，本文围绕“隐私保护+存证留痕”目标，设计并实现一套基于区块链思路的校园心理咨询记录隐私保护与存证系统，以改善传统心理咨询记录管理中存在的可信度不足、过程难追踪和权限边界不清等问题。
系统采用 Next.js 14.2.3、TypeScript、Koa 3.1.1、MySQL 8.0 等技术栈构建前后端分离架构，结合 JWT 认证、bcrypt 密码加密和基于角色的访问控制机制实现多角色业务协同与敏感数据保护。系统实现了登录与注册、心理测评、咨询师申请与预约、咨询记录与反馈、论坛社区、消息与聊天、举报与审核、管理员管理、个人信息与账户安全、统计分析、公告与通知中心等 11 个核心功能模块，并通过统一的存证记录表对关键业务操作进行摘要记录和审计管理。其中，心理测评结果与咨询记录摘要在链上环境配置完成时可调用智能合约执行哈希上链；预约、反馈、论坛内容和举报等业务则先生成链下存证占位记录，为后续进一步扩展链上存证提供接口基础。
本文从隐私保护、数据可追溯性和可信性三个方面对系统进行设计。隐私保护方面，系统通过 RBAC 与分级授权机制约束普通用户、心理咨询师和管理员的数据访问范围；数据可追溯性方面，系统对预约、测评、咨询记录、反馈、论坛内容和举报处理等关键流程生成结构化存证记录，并支持对已上链摘要执行一致性校验；可信性方面，系统通过操作日志、链下记录哈希和链上存证结果共同提升关键业务的可核验能力。在当前测试环境下，系统测试结果显示，该系统能够支撑校园心理咨询的日常业务与管理需求，在隐私保护、审计追踪和业务闭环支撑方面具有较好的工程可行性，并为后续扩展隐私计算与联盟链部署提供了技术基础。
【关键词】心理咨询；隐私保护；区块链存证；访问控制；审计追踪


Abstract
University counseling services involve large amounts of sensitive information. Traditional paper-based records or ordinary information systems often fail to balance privacy protection, process traceability, and accountability, which leads to scattered data, weak access control, and tamper risks. To address these problems, this study designs and implements a campus counseling record system based on blockchain-inspired evidence preservation, with the goal of improving privacy protection, traceability, and credibility in campus counseling management.
The system adopts Next.js 14.2.3, TypeScript, Koa 3.1.1, MySQL 8.0 and related technologies to build a frontend-backend separated architecture. JWT authentication, bcrypt password encryption, and Role-Based Access Control (RBAC) are used to support multi-role collaboration and sensitive data protection. Core functional modules include login and registration, psychological assessment, counselor application and appointment, consultation records and feedback, community forums, messaging and chat, report review, administrative management, personal information and account security, statistical analysis, and the announcement and notification center. Key operations are uniformly recorded through an evidence record table. When the blockchain environment is configured, assessment-result hashes and consultation-record hashes can be written on chain through smart contracts, while other business objects first generate off-chain evidence placeholders for later extension.
The system focuses on three aspects: privacy protection, data traceability, and credibility. Privacy protection is achieved through RBAC and hierarchical authorization. Data traceability is enhanced through structured evidence records and consistency verification between local hashes and on-chain evidence. Credibility is improved through audit logs, evidence records, and on-chain hash confirmation. Test results show that the system can support daily counseling operations and management needs, and provides a practical technical foundation for future privacy computing and consortium-chain deployment.
【Key words】counseling; privacy protection; blockchain evidence; access control; audit trail

1 绪论
1.1 研究背景和意义
1.1.1 研究背景
大学生心理健康问题日益受到高校重视，校内心理咨询工作量也随之增加。随着求助渠道、服务主体和数字媒介不断丰富，校园心理健康服务已经不再局限于传统线下咨询，而是逐步呈现出服务主体多元化、服务过程连续化和服务媒介数字化的发展趋势。在这一背景下，心理咨询记录、测评结果和反馈信息等敏感数据的规范管理问题更加突出，系统不仅要提高服务可及性，还要兼顾隐私保护、过程留痕与责任追溯。
区块链技术在摘要存证和过程追踪方面具有较强优势，与心理咨询记录的可信留痕需求较为契合。但在校园场景中，直接将完整咨询内容上链并不现实，仍需要在隐私与合规之间做出权衡。因此，设计一套"链下存储+链上存证"的分层架构，并通过权限控制、数据分级、审计日志等手段保障隐私，是高校心理咨询信息化的重要方向。
1.1.2 研究意义
本课题面向校园心理咨询业务全流程，构建一套兼顾隐私保护与存证留痕的系统。一方面，通过统一的平台提高咨询流程效率与服务质量；另一方面，通过证据记录与链上存证机制增强关键操作的可追溯性，提升系统可信度与管理合规性，具有较强的现实意义和一定的推广价值。
1.2 研究现状
1.2.1 校园心理健康信息化研究现状
校园心理健康服务的信息化建设，早期更多关注服务可及性、求助机制和组织支持方式。已有研究表明，大学生心理求助行为与求助态度、社会评价和求助可及性密切相关[1][2]；高校朋辈心理互助实践也说明，数字化系统不仅要服务于预约和记录，还要服务于资源分流、陪伴支持和校内协同[3][4]。随着人工智能和数字媒介进入心理服务场景，当事人对 AI 心理咨询在关系感、情感支持和咨询效果上的知觉差异，也进一步表明心理健康信息化系统需要同时兼顾服务便利性、隐私感知和记录规范性[5]。
在心理健康记录与区块链结合方面，相关研究已开始从通用医疗记录场景延伸到心理服务场景。Ettaloui 等提出区块链电子心理健康记录模型，将记录摘要与访问行为纳入可信账本，用于提升心理健康记录的可追溯性与可信共享能力[6]。Jhamba 等面向心理健康机构患者门户构建链上链下结合方案，通过智能合约、BFT 机制与加密存储实现记录防篡改和授权访问[7]。总体来看，现有研究已证明区块链技术可用于心理健康记录场景，但多数成果仍停留在机构原型或通用平台层面，针对高校心理咨询业务中多角色协同、预约到反馈的完整闭环以及校园治理约束的系统化研究仍较少。
1.2.2 隐私保护与可信存证研究现状
在隐私保护与可信共享方面，牛淑芬等提出基于私有链与联盟链结合的电子病历共享方案，并引入可搜索加密与代理重加密机制，以提高跨机构共享的安全性与可用性[8]。巫光福等在联盟链电子健康记录场景中引入匿名隐私算法，说明“链上共享索引、链下保护原文”已成为较稳定的工程模式[9]。宋文鹏等进一步将分布式数字身份、代理重加密与聚合签名结合到医疗数据共享中，使授权行为具备可验证和可审计特征[10]。刘扬等关于多层次区块链医疗数据共享模型的研究进一步说明，链上链下协同架构具有较好的扩展性[11]。此外，ACHealthChain、患者中心授权框架以及加密 RBAC 等研究表明，电子健康记录场景中的链上策略管理、细粒度授权和可审计身份机制已经逐步成熟[12][13][14]。Taloba 等的研究进一步说明，隐私增强型访问控制机制可以与区块链数据管理框架结合使用[15]。
在可信存证与过程审计方面，相关研究已从“数据是否上链”进一步扩展到“关键操作过程是否可验证”。Bonomi 等提出 `B-CoC` 模型，将数字取证中的 chain of custody 过程写入区块链，以支持证据接触、流转和责任确认的可追溯[16]；Onyeashie 等和张川等则从证据共享管理和跨联盟链审计角度，进一步验证了结构化留痕与可验证审计的工程价值[17][18]。姚可凡等关于智能合约存证流程的研究也说明，区块链可与程序化存证流程结合使用[19]。此外，可控匿名研究表明，审计追踪与有限匿名保护可以在同一框架下协同实现[20]。综上，现有研究已经为校园心理咨询系统提供了“链下保存敏感原文、链上记录摘要与授权行为、关键过程保留审计痕迹”的可借鉴路径，但如何围绕预约、测评、咨询记录、反馈和举报等校园关键业务构建完整的全过程存证框架，仍需结合高校实际场景进一步设计。

1.3 研究内容与目标
本研究以校园心理咨询业务为核心，围绕"隐私保护+存证留痕"展开，主要内容与目标包括：梳理校园心理咨询业务流程，明确普通用户、心理咨询师与管理员的职责边界与数据访问需求；设计多角色系统架构，前端采用组件化方式实现分角色界面，后端提供统一业务接口与权限控制；构建心理测评、咨询师申请与预约、咨询记录与反馈、论坛社区、消息与聊天、举报与审核、个人信息与账户安全、统计分析、公告与通知中心等功能模块，满足校园心理服务的完整闭环；设计统一的存证记录与审计机制，确保关键操作过程可追溯，并实现心理测评结果与咨询记录摘要的链上哈希存证能力，同时为预约、反馈、论坛内容和举报等业务保留后续链上扩展接口；完成系统测试与评估，验证功能正确性与可用性，为后续迭代提供依据。






2 技术概述
2.1 区块链技术
区块链是一种分布式账本技术，能够为数据摘要登记、过程追踪和结果校验提供较强的可信支撑。在本系统中，区块链主要用于心理测评结果与咨询记录摘要的可信留痕，关键思路不是直接公开敏感原文，而是采用链下保存业务数据、链上记录摘要与策略的混合架构。因此，本系统将区块链定位为可信存证与审计增强组件，而非原文存储载体。
2.2 智能合约
在本系统中，智能合约并不直接保存完整咨询正文，而是承担摘要哈希登记、时间戳固化、修订版本记录和链上结果返回等职责。系统先在链下对测评结果和咨询记录的关键字段构造规范化摘要，再对摘要执行哈希运算，并将哈希值写入合约。这样既避免了敏感原文直接上链，又保留了后续核验时可对照、可追溯、可审计的证据基础。
2.3 Node.js
Node.js 采用事件驱动和非阻塞 I/O 机制，适合处理本系统中的登录认证、预约提交、消息通知、举报流转与存证补录等高频接口请求。对校园心理咨询平台而言，请求通常具有并发量较高、单次处理链路较短、接口联动较多的特点，Node.js 能够较好地承担这一类服务编排任务。
2.4 Next.js框架
本系统前端采用 Next.js 构建多角色门户界面，利用文件路由和组件化方式组织注册、测评、预约、记录、反馈、论坛和管理端页面。该框架能够较好地兼顾首屏加载效率、页面复用能力和工程可维护性，也便于后续继续扩展移动端适配、统一布局和角色化导航等功能。
2.5 Koa框架
Koa 框架以中间件机制简洁著称，适合搭建强调认证、授权、参数校验和异常处理一致性的 REST API 服务。在本系统中，身份认证、角色鉴权、请求日志、统一错误响应和静态资源访问限制均通过中间件链路完成，能够清晰划分公共处理逻辑与具体业务逻辑，提升后端接口的可维护性。
2.6 MySQL数据库
MySQL 作为关系型数据库，能够较好地支撑用户、预约、咨询记录、反馈、论坛、举报、通知和存证等多个业务实体之间的关联关系。系统通过主键、外键、状态字段和时间字段维护业务流转一致性，并为统计分析、责任追溯和链下核验提供稳定的数据基础，因此适合作为本系统的核心持久化存储方案。
2.7 JWT认证
JWT 认证机制用于维护登录态和角色信息，后端在用户通过邮箱和密码验证后签发 Token，前端在后续请求中附带 Token 访问受保护接口。系统再结合 RBAC 机制，对普通用户、心理咨询师和管理员进行细粒度授权，确保不同角色只能访问与自身职责相匹配的数据和功能，从而提升接口鉴权的一致性和可追踪性。
2.8 TypeScript
TypeScript 为前后端统一的数据结构约束提供了良好支持。无论是预约状态、咨询记录字段、反馈载荷，还是存证记录返回结果，都可以在编译阶段进行类型检查，降低字段拼写错误、空值处理不当和接口结构不一致带来的隐患。对于涉及敏感数据和多模块协作的校园心理咨询系统而言，类型安全直接关系到系统维护过程中的稳定性和可测试性。

用户登录与令牌签发核心代码：
```ts
export async function loginUser(input: LoginInput) {
  const user = await findUserByEmail(input.email);
  if (!user) throw new UnauthorizedError("账号或密码错误");
  if (user.isDisabled) throw new UnauthorizedError("账号已被禁用");
  if (!(await bcrypt.compare(input.password, user.password))) throw new UnauthorizedError("账号或密码错误");
  await updateUserLastLogin(user.id);
  const token = jwt.sign({ sub: user.id, role: user.role }, env.jwtSecret, { expiresIn: "1d" });
  return { token, user: toSafeUser(user) };
}
```

心理测评与测评存证模块在用户完成答题后，由后端按照量表规则计算测评分值与等级，并将结果写入测评结果表。随后系统自动创建对应的测评存证记录，对测评结果构造规范化 JSON 摘要并计算 keccak256 哈希；当测评存证合约已完成部署且链上配置可用时，系统调用 AssessmentEvidenceRegistry 合约写入测评结果摘要哈希，并将交易哈希、区块高度、链标识、合约地址、修订版本和链上记录时间回填到本地存证记录中。若链上环境未配置或调用失败，则保留待同步状态，以便后续确认与校验。该设计强调“敏感原文链下保存、摘要哈希链上登记、失败后可补录确认”的实现逻辑。心理测评页面如图5-3所示。



图 5-3 心理测评页面

心理测评存证同步核心代码：
```ts
export async function syncAssessmentEvidence(record: AssessmentResultRecord) {
  const evidence = await ensureEvidencePlaceholder({ targetType: "ASSESSMENT", targetId: record.id, summary: "心理测评结果哈希存证" });
  try {
    const chainResult = await recordAssessmentEvidenceOnChain(record);
    if (!chainResult) return evidence;
    return updateEvidenceRecordSync(evidence.id, { status: "RECORDED", recordHash: chainResult.recordHash, txHash: chainResult.txHash, blockNumber: chainResult.blockNumber, revision: chainResult.revision });
  } catch (error) {
    const message = error instanceof Error ? error.message.slice(0, 1000) : "心理测评上链失败";
    return updateEvidenceRecordSync(evidence.id, { status: "PENDING", syncError: message });
  }
}
```

咨询记录创建与存证同步核心代码：
````ts
export async function createRecord(counselorId: string, payload: ConsultationInput) {
  const appointment = await findAppointmentById(payload.appointmentId);
  if (!appointment) throw new BadRequestError("预约不存在");
  if (appointment.counselorId !== counselorId) throw new UnauthorizedError("无权创建该预约的记录");
  if (await findConsultationRecordByAppointment(payload.appointmentId)) throw new BadRequestError("该预约已存在咨询记录");
  const record = await createConsultationRecord({ appointmentId: payload.appointmentId, userId: appointment.userId, counselorId, summary: payload.summary ?? null, isCrisis: payload.isCrisis ?? false });
  const evidence = await syncConsultationEvidence(record);
  return { record, evidence };
}
```

7 总结与展望
7.1 论文工作总结
本文围绕校园心理咨询场景中“敏感数据隐私保护不足、关键记录难以追溯、业务流程缺乏可信留痕”三个核心问题，设计并实现了基于区块链存证思想的校园心理咨询记录隐私保护与存证系统。系统从校园心理咨询实际业务出发，构建了登录与注册、心理测评、咨询师申请与预约、咨询记录与反馈、论坛社区、消息与聊天、举报与审核、管理员管理、个人信息与账户安全、统计分析、公告与通知中心等功能模块，并通过角色权限控制、分级展示、审计日志和存证记录机制实现对关键业务数据的分级管理与过程留痕。对于心理测评结果与咨询记录，系统进一步实现了摘要哈希的链上登记与链下核验逻辑；对于预约、反馈、论坛内容和举报等业务，则通过统一的存证占位记录纳入审计框架。结合系统实现与测试结果可以看出，本文提出的设计方案能够较好支撑校园心理咨询工作的日常业务需求，也说明“链下存储原文、链上存证摘要”的技术路线在校园心理咨询场景中具有较好的可行性，同时体现了多角色协同管理与关键操作可追溯设计的实际应用价值。
7.2 存在问题与改进方向
尽管本文完成了系统设计、实现与功能验证，但仍存在一定不足。首先，当前系统的链上存证主要基于本地或测试环境进行验证，尚未在真实联盟链或长期运行环境下开展持续性测试，对复杂网络条件和实际运维问题的适应性仍需进一步检验。其次，当前真正执行链上哈希写入的业务主要集中在心理测评结果和咨询记录，预约、反馈、论坛内容和举报等业务仍以链下存证记录与审计日志为主，后续仍需继续扩大链上存证覆盖范围。再次，系统在内容治理方面仍以基础审核流程为主，对于敏感词识别、异常行为检测、举报分级处置等能力的支持还不够完善。在评估方面，本文更侧重系统功能实现与可行性验证，在大规模真实用户数据条件下的性能评估、可用性评估和危机预警分析仍有继续深化的空间。在审计扩展方面，系统尚未完成跨系统、跨机构或跨联盟链场景下的协同验证，后续仍需进一步完善可验证审计能力。因此，后续研究可围绕链上部署优化、存证范围扩展、智能审核增强和数据分析能力扩展等方向进一步完善。
7.3 对未来展望
未来工作可从三个方面继续推进。第一，在现有测评结果与咨询记录摘要链上存证的基础上，进一步将预约、反馈、论坛内容和举报处理等关键操作逐步扩展到智能合约存证流程中，实现更完整的自动化链上留痕与验证。第二，进一步完善联盟链或许可链部署方案，增强链上存证模块在真实校园环境中的稳定性、可扩展性与可维护性。第三，可在现有链上链下混合架构基础上继续引入加密 RBAC 等隐私增强机制，提升敏感数据共享与访问控制的安全性，并继续优化移动端适配、用户体验设计和智能辅助能力，使校园心理咨询服务在安全性、规范性和可达性方面得到进一步提升，从而推动相关研究由原型验证走向更高层次的实际应用。
