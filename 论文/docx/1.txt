摘    要
高校心理咨询工作涉及大量敏感信息，传统纸质记录或普通信息系统难以兼顾隐私保护、过程留痕与责任追溯，容易出现数据分散、权限控制薄弱、记录可篡改等问题。针对上述现状，本文围绕“隐私保护+存证留痕”目标，设计并实现一套基于区块链混合存证架构的校园心理咨询记录隐私保护与存证系统，以改善传统心理咨询记录管理中存在的可信度不足、过程难追踪和权限边界不清等问题。
系统采用Next.js 14.2.3、TypeScript、Koa 3.1.1、MySQL 8.0等技术栈构建前后端分离架构，结合JWT认证、bcrypt密码加密和基于角色的访问控制机制实现多角色业务协同与敏感数据保护。系统实现了登录与注册、心理测评、咨询师申请与预约、咨询记录与反馈、论坛社区、消息与聊天、举报与审核、管理员管理、个人信息及账户安全、统计分析、公告与通知中心等11个核心功能模块，并通过统一的存证记录表对关键业务操作进行摘要记录和审计管理。系统采用“链下存储原文、链上登记摘要”的混合架构，其中心理测评结果与咨询记录摘要通过智能合约写入链上存证层。
本文从隐私保护、数据可追溯性和可信性三个方面对系统进行设计。隐私保护方面，系统通过RBAC与分级授权机制约束普通用户、心理咨询师和管理员的数据访问范围；数据可追溯性方面，系统对预约、测评、咨询记录、反馈、论坛内容和举报处理等关键流程生成结构化存证记录，并支持对已登记链上摘要执行一致性校验；可信性方面，系统通过操作日志、链下记录哈希和链上存证结果共同提升关键业务的可核验能力。系统测试结果表明，该系统能够支撑校园心理咨询的日常业务与管理需求，在隐私保护、审计追踪和业务闭环支撑方面具有较好的工程可行性，并为后续扩展隐私计算与联盟链部署提供了技术基础。

Abstract
University counseling services involve large amounts of sensitive information. Traditional paper-based records or ordinary information systems often fail to balance privacy protection, process traceability, and accountability, which leads to scattered data, weak access control, and tamper risks. To address these problems, this study designs and implements a campus counseling record system based on a blockchain-backed hybrid evidence architecture, aiming to improve privacy protection, traceability, and credibility in campus counseling management.
The system adopts Next.js 14.2.3, TypeScript, Koa 3.1.1, MySQL 8.0 and related technologies to build a frontend-backend separated architecture. JWT authentication, bcrypt password encryption, and Role-Based Access Control (RBAC) are used to support multi-role collaboration and sensitive data protection. Core functional modules include login and registration, psychological assessment, counselor application and appointment, consultation records and feedback, community forums, messaging and chat, report review, administrative management, personal information and account security, statistical analysis, and the announcement and notification center. Key operations are uniformly recorded through an evidence record table. The system adopts a hybrid model in which raw records are stored off chain while normalized summaries are written to the blockchain evidence layer through smart contracts.
The system focuses on three aspects: privacy protection, data traceability, and credibility. Privacy protection is achieved through RBAC and hierarchical authorization. Data traceability is enhanced through structured evidence records and consistency verification between local hashes and on-chain evidence. Credibility is improved through audit logs, evidence records, and on-chain hash confirmation. Test results show that the system can support daily counseling operations and management needs, and provides a practical technical foundation for future privacy computing and consortium-chain deployment.

1 绪论
1.1 研究背景和意义
1.1.1 研究背景
大学生心理咨询业务包含预约、测评、咨询记录、反馈等多个环节，其中需要较强的隐私性，系统搭建面临隐私保护、过程追踪、责任追溯等问题。本文采取“链下存储原文、链上登记摘要”的框架，将区块链理解为链上存证层，使其能够顾及隐私、合规、可验证性；开发与测试过程中实现待同步机制，用于后续的补录和确认。
1.1.2 研究意义
本课题面向校园心理咨询服务全程，设计一套含隐私保护与存证查核的系统。该系统为心理咨询服务提供了便利，以及通过链上链下混合存证的方式保证重要操作具有可追溯性。
1.2 研究现状
1.2.1 国内研究现状
校园心理健康服务的信息化建设初期主要聚焦于服务可及性、求助形式和组织形式。有研究发现大学生心理求助行为与其心理求助态度是密切相关的[1]。还有一些研究发现社会评价和求助的可及性对大学生心理求助行为有影响[2]。从高校朋辈心理互助实践来看，数字化系统不仅要服务于预约、记录，还需要服务于陪伴支持[3]。还有一些研究指出，校园心理服务平台也要兼顾校内协同需求[4]。人工智能和数字媒介进入心理服务场景后，当事人对 AI 心理咨询在关系、感情和心理“咨询效果”上的知觉差异，也证实了心理健康信息化系统需要兼顾心理服务的便捷性、隐私意识、记录规范性[5]。
在隐私保护、可信共享方面，国内针对医疗健康数据方面，学者进行了大量研究工作。牛淑芬等构建了基于区块链的电子病历数据共享方案，引入可搜索加密、代理重加密等方式提高基于区块链跨机构共享安全性、可使用性[6]。巫光福等在联盟链电子健康记录共享的场景下引入匿名隐私算法，说明了链上共享索引、链下保护原文是目前比较稳定的工程实现[7]。宋文鹏等将分布式数字身份、代理重加密、聚合签名结合起来应用于医疗数据共享，使得访问授权具有可验证、可审计性[8]。总体来看，国内研究已为校园心理咨询系统提供了链下保存敏感原文、链上记录摘要与授权行为的可借鉴思路，但如何围绕预约、测评、咨询记录、反馈与举报等关键业务构建全过程存证框架，仍需结合高校实际场景进一步设计。
1.2.2 国外研究现状
在心理健康记录与区块链结合方面，国外研究已开始从通用医疗记录场景延伸到心理服务场景。Ettaloui 等提出区块链电子心理健康记录模型，将记录摘要与访问行为纳入可信账本，用于提升心理健康记录的可追溯性与可信共享能力[9]。Jhamba 等面向心理健康机构患者门户构建链上链下结合方案，通过智能合约、BFT 机制与加密存储实现记录防篡改和授权访问[10]。de Aguiar 等针对共享医疗影像场景提出基于区块链的访问追踪协议，通过不可篡改日志与令牌机制增强共享过程中的责任定位与可验证性[11]。Puneeth 等强调以患者为中心的授权控制思路，使敏感数据共享建立在可验证授权基础之上[12]。Jakhar 等从电子健康记录管理出发，进一步将区块链、隐私保护与访问控制框架化整合[13]，Taloba 等则结合加密 RBAC 提升医疗数据管理中的细粒度保护能力[14]。
国外研究的结果是：在数据是否上链的基础上进一步做到了关键操作过程是否可被验证，为校园心理咨询系统提供了一个参考方向：链下保留数据敏感原文、链上保留摘要和授权记录、关键操作可保留存证审计痕迹。但如何结合学校情况进行预约、测评、咨询记录、反馈、举报等校园关键业务全过程存证的设计，还需进一步研究。
1.3 研究内容与目标
我们以校园心理咨询业务为原型，完成了需求分析、系统设计、功能实现和系统测试。整个系统采取“链下存储原文，链上登记摘要”的链式存证混合架构模式，实现了登录注册、测验、预约、咨询登记、论坛、消息、举报、统计、后台管理等模块的功能。
2 技术概述
2.1 区块链技术
区块链技术是本系统实现存证与核验能力的重要基础。相关研究表明，区块链能够为数据摘要登记、过程追踪和结果校验提供可信支撑[15]。系统采用“链下保存原文、链上登记摘要”的混合存证模式，将原文保存在数据库中，仅把规范化摘要及其哈希值登记到链上，利用区块链的不可篡改和可追踪的特点。
在本系统中，区块链主要服务于关键数据的摘要登记、过程留痕和后续核验，而不直接承担全部业务处理。登录注册、测评、预约、咨询记录、论坛、消息、举报、统计和后台管理等模块仍运行在传统 Web 架构下，链上部分则为关键记录提供可信凭据。
2.2 智能合约
智能合约是部署在区块链上的程序，在满足条件时可以按预设规则自动执行。系统实现了 `AssessmentEvidenceRegistry` 和 `ConsultationEvidenceRegistry` 两个存证合约，分别对应心理测评结果和咨询记录摘要的登记。业务系统生成规范化摘要并计算哈希后，会调用相应合约完成摘要写链，后续也可以基于链上结果进行核验。
2.3 Node.js
Node.js 是一种基于事件驱动和非阻塞 I/O 模型的服务端运行环境，比较适合处理高频接口请求。本系统前后端都采用 JavaScript/TypeScript 技术体系，Node.js 也有助于统一开发语言，降低联调和维护成本。这样既方便开发，也便于后续扩展接口和管理通用数据结构。
2.4 Next.js框架
Next.js 是在 React 基础上构建的应用框架，具有页面路由清晰、组件化开发方便等特点。对于本系统而言，前端不仅包含普通用户端，还包括心理咨询师端和管理员端，因此使用 Next.js 有助于统一组织登录、测评、预约、咨询记录、论坛和管理端等页面。
2.5 Koa框架
Koa 是一个轻量级的 Node.js Web 框架，适合构建 REST API 服务。本系统后端需要处理登录鉴权、参数校验、异常捕获、权限控制和结果返回等请求流程，这些逻辑都适合通过 Koa 的中间件机制进行组织。在实际实现中，Koa 主要承担后端 API 层的组织工作。前端提交的注册、登录、预约、消息、举报和管理等请求，都会通过 Koa 路由转发至对应控制器，再调用服务层和数据层完成处理。
2.6 MySQL数据库
MySQL 是一种常用的关系型数据库，适合保存具有明确实体关系的业务数据。校园心理咨询系统中涉及用户、咨询师、预约、咨询记录、测评结果、反馈、论坛内容、举报信息、通知消息和存证记录等多类数据，这些数据之间具有较强关联性，因此采用 MySQL 进行统一管理较为合适。
2.7 JWT认证
JWT （JSON Web Token）是一种常用的无状态身份认证机制，适合在前后端分离系统中维护登录态和身份信息。用户登录成功后，后端会签发包含用户身份和角色信息的 Token，前端在后续请求中携带该 Token，后端则基于 Token 内容识别访问者身份。
2.8 TypeScript
TypeScript 是 JavaScript 的超集，在保留原有灵活性的基础上引入了静态类型检查能力。对于本系统而言，前后端都涉及大量结构化数据，例如用户信息、预约记录、测评结果、咨询记录、通知消息和举报数据等。如果缺少明确的类型约束，就较容易出现字段命名不一致、数据类型错误和参数遗漏等问题。因此，本系统在前后端开发中均使用 TypeScript，对请求参数、响应结果和业务实体进行统一定义。这样做有助于在开发阶段尽早发现字段不匹配问题，也能提高代码的可读性和可维护性。

用户登录与令牌签发核心代码：
```ts
export async function loginUser(input: LoginInput) {
  const user = await findUserByEmail(input.email);
  if (!user) {
    throw new UnauthorizedError("账号或密码错误");
  }
  if (user.isDisabled) {
    throw new UnauthorizedError("账号已被禁用");
  }
  const isMatch = await bcrypt.compare(input.password, user.password);
  if (!isMatch) {
    throw new UnauthorizedError("账号或密码错误");
  }
  await updateUserLastLogin(user.id);
  const token = jwt.sign(
    { sub: user.id, role: user.role },
    env.jwtSecret,
    { expiresIn: "1d" },
  );
  return {
    token,
    user: toSafeUser(user),
  };
}
```
5.2 心理测评存证模块的实现
心理测评存证模块：用户答题完毕后，后端根据量表算法算出测评分和测评等，写入测评结果表中，再自动生成测评存证，对测评结果构造规范化的JSON摘要，计算keccak256摘要哈希；测评存证合约若已部署到位、链上可达，利用 AssessmentEvidenceRegistry 合约写入测评结果摘要哈希，把交易哈希、块号、链号、合约地址、版本、链上记录时间回写到本地存证记录里；如果在开发测试环境里，链上存证层配置没有写入或者链上写入失败，留待通知待同步，以便靠后面补齐确认而不是放弃用链上存证。该设计强调“敏感原文链下保存、摘要哈希链上登记、失败后可补录确认”的实现逻辑。如图5-3所示。

图5-3 心理测评存证页面

心理测评存证智能合约核心代码：
pragma solidity ^0.8.20;
contract AssessmentEvidenceRegistry{
    struct Evidence{bytes32 recordHash;uint256 revision;uint256 recordedAt;}
    mapping(string=>Evidence) public evidences;
    event AssessmentRecorded(string indexed assessmentId,bytes32 indexed recordHash,uint256 revision);
    function recordAssessment(string calldata assessmentId,bytes32 recordHash) external {
        uint256 revision=evidences[assessmentId].revision+1;
        evidences[assessmentId]=Evidence(recordHash,revision,block.timestamp);
        emit AssessmentRecorded(assessmentId,recordHash,revision);
    }
}

隐私保护核心代码如下：
```ts
export async function authenticate(ctx: Context, next: Next): Promise<void> {
  const authHeader = ctx.headers.authorization;
  if (!authHeader || !authHeader.toLowerCase().startsWith("bearer ")) {
    throw new UnauthorizedError("缺少访问令牌");
  }
  const token = authHeader.slice(7).trim();
  const payload = await verifyToken(token);
  const accessInfo = await findUserAccessInfo(payload.sub);
  if (!accessInfo) {
    throw new UnauthorizedError("账号不存在或已被删除");
  }
  if (accessInfo.isDisabled) {
    throw new UnauthorizedError("账号已被禁用");
  }
  ctx.state.user = {
    ...payload,
    role: accessInfo.role,
  };
  await next();
}
```

7 总结和展望
7.1 论文工作总结
本文针对校园心理咨询场景中的隐私保护、跟踪追溯和可信留痕问题，设计和实现了一种基于区块链的存证思想的校园心理咨询记录的隐私保护与存证系统。系统实现了校园心理咨询系统的登录、注册、测评、预约、咨询记录、论坛、消息、举报、后台管理、安全中心、统计分析、公告通知等模块，实现了通过角色权限、日志记录和记录存证对关键业务数据进行划分和过程记录。实现了“链下保存原文、链上记录存证”的工程化方案。
7.2 存在问题与改进方向
尽管本文实现了一些系统的成功的设计、实现和功能试验，仍然有所局限。目前的链上存证只是以本地链上或测试链上进行了验证，还没有使用实际的联盟链或持续的一年时间内长期在线验证测试；而且举报程度测定和大规模真实用户的性能测试方面还有待于进一步研究。以后的改进还可以结合可控匿名的思想进一步平衡追溯性和隐私性[20]。
7.3 对未来展望
未来工作主要可以从2个方向上进行探索：（1）实现联盟链或许可链的部署，改善链上存证模块在真实应用场景（如校园）中使用的稳定、可伸缩性、可维护性；（2）在现有混合型基础上继续增加隐私保护能力和优化移动端和智能辅助功能，推动系统从原型走向更高层次的应用。
